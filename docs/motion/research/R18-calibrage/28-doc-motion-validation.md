# Validation locale de la documentation Motion — 13 novembre 2026

Le plan [23](23-doc-motion-plan.md) reste partiellement validé. Sur l'état local non commité, `./node_modules/.bin/astro build`, exécuté depuis `apps/doc`, s'est terminé avec le code 0. Le build a signalé notamment une classe CSS générée contenant `stroke: var(...)`, invalide. Les pages Motion, `/animations/` et l'index Pagefind ont été générés.

L'investigation ultérieure localise cet avertissement dans le commentaire de `packages/ui-react/src/tests/Button.spec.tsx:93` : l'exemple abrégé `!stroke-[var(...)]` est interprété comme une classe par le scanner Tailwind. Un scan ciblé de ce seul fichier avec `@tailwindcss/oxide` 4.3.3 retourne cet exemple et la classe valide `!stroke-[var(--button-progress-color)]`. La directive `@source` de `apps/doc/src/styles/global.css:8` inclut le paquet React local, y compris ce test. `git blame` attribue le commentaire au commit `17e6aa91b` du 8 août 2026 ; la directive existait déjà dans `HEAD`, avant l'ajout non commité de l'import Motion. Deux rapports d'audit de septembre signalent aussi cet avertissement comme préexistant. Cette classe fantôme ne relève pas de Motion ; aucune modification du test Button ou de la configuration Tailwind n'est faite ici. La classe réellement utilisée par Button contient bien le nom complet de la variable.

Les fichiers statiques `dist/client` ont ensuite été servis par `python3 -m http.server 4322 --bind 127.0.0.1 --directory dist/client`. Depuis `apps/doc`, `MOTION_DOC_URL=http://127.0.0.1:4322 MOTION_BROWSERS=chromium,firefox node --test tests/motion.browser.test.mjs` a réussi : quatre tests, zéro échec. Navigateurs Playwright observés : Chromium 156.0.8078.4 et Firefox 157.0. La suite couvre les cinq URL, la navigation statique et la démonstration sans JavaScript, des changements de politique et de préférence réduite, l'héritage et une surcharge dans Shadow DOM, ainsi que la sélection du rail avec JavaScript. Elle ne remplace pas un contrôle manuel complet du clavier ou de l'accessibilité, ni une validation de tous les navigateurs.

Avec `MOTION_BROWSERS=webkit`, les deux tests échouent avant ouverture d'une page : Playwright indique les bibliothèques système manquantes `libevent-2.1-7t64` et `libmanette-0.2-0`. WebKit et Safari réel restent donc non vérifiés. Le serveur statique local ne valide pas l'adaptateur Vercel ni un déploiement. Les premiers essais sur serveur de développement ont échoué avant disponibilité du serveur ou expiré ; ils ne constituent pas un résultat sur le site construit.
