# Documentation publique Motion — plan incrémental

> **Exécution :** `superpowers:executing-plans`. Ce document prépare la documentation ; il ne déclare aucune famille achevée et ne modifie pas le site.

**Objectif :** donner aux utilisateurs d’Astro et des autres environnements un point d’entrée fiable sur les capacités réellement disponibles de `@udixio/motion`, puis enrichir la documentation au rythme des familles livrées.
**Architecture :** une section `/motion` accessible depuis le rail, une roadmap avec une source de vérité explicite et des pages ajoutées uniquement avec leur capacité. `/animations` reste accessible et identifiée comme documentation des anciennes utilités ; les liens entrants continuent de fonctionner.
**Technologies :** Astro, MDX, CSS, composants du site, tests navigateur et build Nx.
**Spec :** `docs/superpowers/specs/2026-11-03-udixio-motion-design.md` §5 et phases 3–5 ; état observé dans `packages/motion`, `apps/doc/src/pages/animations.astro` et `docs/motion/research/R18-calibrage/22-f2-search.md`.

## État et règles de publication

- F1 est **partielle et expérimentale** : tokens M3, résolveurs et CSS statique existent ; personnalisation, intégration runtime complète et syntaxes Tailwind/adaptateurs ne sont pas livrées. Distances et stagger restent provisoires, à calibrer. Les schemes CSS et TypeScript sont indépendants.
- F2 est **partielle** : Search consomme les tokens pour deux contours ; elle ne démontre ni les propriétés discrètes, ni les tailles auto, ni la famille entière. Sa page actuelle est `apps/doc/src/data/components/search.overview.mdx`.
- F20 est **partielle** : le CSS expose une échelle liée au système et à l’attribut HTML ; il ne force pas toutes les animations à la respecter. Les providers bruts exigent une politique explicite du consommateur. Ne pas annoncer une politique runtime générale livrée.
- Les autres familles sont **prévues / non livrées comme API publique de famille**, même si des fondations, providers, tests ou verbes figurent dans le manifeste. `supportedVerbs` décrit la validation expérimentale, pas une promesse d’API d’animation complète. `RUNTIME_KEY` est réservé, le runtime partagé n’est pas enregistré. Le package est en construction, version `0.0.0` dans le dépôt ; vérifier la publication effective avant toute instruction d’installation.
- Le tableau navigateur/provider distingue « non vérifié », « fondation testée » et « famille livrée » ; ne jamais déduire une compatibilité globale de la présence d’un provider ou de `CSS.supports`. Consigner moteur, version, scénario et résultat vérifié avant de publier une cellule positive ; une absence de résultat reste inconnue.
- Ne pas retirer `anim-*` ni leurs exemples dans cette tranche : la suppression relève de la phase 4 et d’une migration séparée. Les noms Motion des docs de composants peuvent aussi désigner l’ancienne dépendance `motion` ; ne pas les assimiler automatiquement à `@udixio/motion`.

## Tâche 2 — Tokens, réduction et démonstration

**Fichiers :** créer `apps/doc/src/pages/motion/tokens.astro`, `accessibility.astro` et, si nécessaire, un composant de démo local à `apps/doc/src/components/` ; modifier `apps/doc/package.json`, son lockfile et le point d’import CSS choisi.

- [ ] Documenter l’import `@import '@udixio/motion/motion.css';` dans la feuille de style du document, après déclaration de la dépendance ; donner aussi un exemple d’import CSS côté application compatible avec le bundler. Tester le chemin réellement résolu en build et, avant de parler d’installation npm, vérifier qu’une version est effectivement publiée. Le CSS inclut les courbes et ressorts générés ; il ne suffit pas de définir un token pour animer.
- [ ] Décrire les durées et easings, ressorts `--udx-motion-spring-{fast,default,slow}-{spatial,effects}-{duration,easing}`, fallback cubic-bezier et sélection CSS `linear()` selon support. Préciser que le scheme CSS `data-motion-scheme="standard"` et `defineTokens({ scheme: 'standard' })` sont indépendants, et que distances/stagger sont provisoires. Les exemples doivent utiliser les noms exacts des exports et variables présents au moment de la livraison.
- [ ] Expliquer `--udx-motion-scale` : défaut 1 ; `html[data-motion-policy="reduce"]` ou préférence système réduite donne 0 au document ; `auto`, absence ou valeur inconnue suivent le système. Multiplier explicitement la durée d’une transition CSS par ce scale ne suffit pas à garantir la sécurité de tous les effets : adapter ou supprimer translation, boucles et contenu essentiel selon leur contexte. Les providers bruts ne consomment pas automatiquement cette politique.
- [ ] Décrire la limite Shadow DOM : le sélecteur HTML ne traverse pas la frontière, mais le scale défini par le CSS du document peut être hérité ; une surcharge locale peut le contourner. Sans ce CSS, l’attribut ne garantit pas la réduction dans le shadow. Le comportement spécifique de Search (réduction système même sans stylesheet, repli 200 ms, courbe de repli et attribut en DOM ordinaire) reste documenté comme tel, pas généralisé.
- [ ] Fournir une démo CSS courte sans script : une case à cocher native avec `label` explicite pilote via `:checked` une transition de couleur ou d’opacité sur un élément décoratif, durée calculée avec le scale ; son état coché reste visible et compréhensible sans animation. Une seconde case native étiquetée « Réduire le mouvement dans cette démonstration » applique localement une durée nulle via CSS, sans modifier la préférence globale ni prétendre modifier la politique HTML. Montrer le code source. Éviter boucle automatique et contenu essentiel caché. Avec JavaScript désactivé, vérifier Tab, focus visible, activation Espace, nom et état accessibles des deux cases, changement durable et réversible de l’état visuel, ainsi que la réduction locale ; vérifier séparément préférence système réduite et attribut HTML. Expliquer que l’état final reste accessible sans animation.
- [ ] Vérifier Astro en SSR/build : aucun accès à `window` ou `document` au chargement serveur ; HTML et CSS initiaux utilisables avant hydratation. Tester aussi le rendu hydraté si un composant interactif est nécessaire, sans différence d’état initial ni clignotement. La démo CSS seule doit fonctionner sans hydratation.
