# M3 — Annotations des choix M1, M2, M4, M5 (R13, étape 2)

Jugement de cohérence contre §8 du spec (§8.0 fondations, §8.0 bis surface, §8.1 grammaire `data-motion` / verbes / presets). Les « ? » signalent un point à trancher par spike ou par le greffier. Aucun nouveau choix.

## M1

- M1-L01 : neutre — +primitive unique « avant / après / inversion » en une passe de lecture / −mutation synchrone obligatoire, changement asynchrone non couvert / conflits: M5-L01, M1-L02, M2-L01 / cohérence: exception: `motion.layout` impératif absent de la surface §8.0 bis #3, à fusionner dans `mutate` de M5-L01
- M1-L02 : conteste — +Svelte `$effect.pre` est un vrai point pré-mutation / −Angular `afterRender` est un hook post-rendu : il ne garantit pas une capture avant mutation, à prouver ou à retirer / conflits: M3-L03, M5-L01, M4-L01 / cohérence: exception: mécanique divergente par environnement, acceptable car la surface reste identique (§8.0 bis #3), à déclarer
- M1-L03 : conteste — +zéro JS pour les propriétés interpolables ; `data-hover` évite le polling / −le miroir est un état écrit par JS, contraire à §4.3 et à la règle §8.0 bis (Tailwind règle les états) ; deux sources de vérité ; écart tactile / conflits: M4-L02, M2-L02, M3-L04, M5-L02 / cohérence: exception: attributs écrits par le moteur hors grammaire, à justifier ou à retirer
- M1-L04 : conteste — +garde les sept verbes / −`layout` désigne la géométrie et l'élément partagé (§8.1 #2) : impropre pour une couleur (C5) ; `carry` change de sens selon la cible / conflits: M5-L03, M2-L03, M3-L06, M4-L03 / cohérence: exception: contredit la définition de `layout` ; `emphasize` existe déjà pour les états, l'exception n'est pas justifiée
- M1-L05 : valide — +vitesse exacte pour un ressort analytique, `velocity.source` honnête, pas de saut en `carry` / −limité aux ressorts à un degré de liberté ; bascule natif → JS en cours de mouvement / conflits: M3-L06 (estimé, compatible), M5-L03 (carry) / cohérence: ok (§8.0 bis #4 ; ressort par token, R12 M1-V05)
- M1-L06 : valide — +hauteur `auto` en CSS pur sur `defaults`, sans JS et sans `display:none` ; le panneau reste monté / −`hidden="until-found"` non vérifié ; coût de layout par frame / conflits: M5-L04, M2-L04, M4-L04, M3-L07 / cohérence: exception: ni `data-motion` ni verbe, donc contraire à M5-L04 (`collapse` → `layout`) ; à arbitrer, pas à cumuler
- M1-L07 : conteste — +identité par attribut, FLIP croisé, pas de snapshot image / −valeur libre (un id), contraire à la référence seule de §8.1 #1 et à M5-L05 ; erreur silencieuse si dupliqué / conflits: M5-L05, M2-L05, M4-L05, M3-L08 / cohérence: exception: valeur libre, interdite par §8.0 bis pour `data-motion`
- M1-L08 : valide — +une seule mécanique de navigation pour Astro, SvelteKit, Angular, React ; cross-document natif / −transition document-scopée qui chasse la précédente ; Firefox sans cross-document / conflits: M4-L07, M2-L07, M5-L06, M4-L08 / cohérence: ok (action et non verbe, R12 M3-V03) ; `motion.navigate` est une forme noyau à inscrire dans §8.0 bis #3
- M1-L09 : valide — +les frères ne sautent pas pendant la sortie / −`position:absolute` casse largeurs en % et grilles ; `sibling-index()` compte les sortants / conflits: M4-L09 (sortie sur place, contraire), M2-L10 (même idée) / cohérence: exception: défaut de `disappear` lié au contexte liste et stagger qui exclut les sortants (contre `sibling-index`) ; à inscrire au manifeste
- M1-L10 : valide — +`finished` sur `getAnimations({ subtree: true })`, pas `transitionend` ; garde-fou temporel / −`getAnimations` force un recalcul de style ; le garde-fou masque une animation bloquée / conflits: M5-L08 (`leaving` ou `exiting`), M2-L09, M4-L10, M3-L10 (nom d'attribut) / cohérence: exception: attribut écrit par le moteur, même statut que M5-L08 ; conforme à `finished` ne rejette jamais (§8.0 #4)

## M2

- M2-L01 : neutre — +une règle FLIP par environnement, pas de lecture forcée en HTML pur / −mémoire périmée si le mouvement n'est pas observé ; une lecture de plus par nœud modifié / conflits: M4-L01, M3-L02 (même mécanisme) / cohérence: ok (mesure interne, aucune grammaire) ; « `effect()` Angular » à confirmer ?
- M2-L02 : valide — +aucun polling ; erreur claire pour `hover:justify-end` / −pont `@property` fragile (R4), réservé au diagnostic / conflits: M5-L02, M1-L03, M4-L02 / cohérence: ok (§8.0 bis : état = attribut, Tailwind par variantes ; erreur de build, M5-S10)
- M2-L03 : valide — +aucun verbe nouveau ; le CSS reste seule source de rendu (§4.2) / −`@property` obligatoire, sinon saut silencieux ; WAAPI sans vitesse / conflits: M5-L03, M3-L06, M4-L03, M1-L04 / cohérence: exception: `carry` par défaut pour `emphasize`, contraire à R12 M5-choix (`restart`) ; `@property` comme unité d'animation justifié par §4.2
- M2-L04 : valide — +contenu présent pour la recherche et les ancres ; `inert` immédiat / −`interpolate-size` Chromium seul ; `::details-content` et `until-found` à vérifier / conflits: M1-L06, M5-L04, M4-L04, M3-L07 / cohérence: ok (`inert` posé à la fermeture et `hidden` au `finished`, §8.0 #2 ; fondu réduit, §8.1 corrigé)
- M2-L05 : valide — +registre global unique, interrogeable par les agents, partagé entre îles / −clé orpheline silencieuse ; îles hydratées à des moments différents / conflits: M5-L05, M1-L07, M4-L05, M3-L08 / cohérence: exception: `data-motion="layout"` prend un verbe comme nom (§8.1 #1 réserve `data-motion` au nom d'animation) ; clé libre à typer comme M5-L05
- M2-L06 : conteste — +un seul rendu à tester, reprise avec vitesse / −contredit C3 et §4.5 (natif d'abord) ; moins fluide que le snapshot VT sur les grands changements / conflits: M4-L05 (match-element), M2-L07 / cohérence: exception: contredit C3 et §4.5 ; à démontrer par spike avant toute adoption
- M2-L07 : valide — +intégration sans verbe, natif réel, sans fallback fragile / −un adaptateur par routeur ; `data-motion-transition` double le rôle de `data-motion-shared` / conflits: M1-L08, M4-L07, M5-L06, M4-L08, M2-L06 / cohérence: exception: navigation hors verbe, justifiée ; l'option `data-motion-transition` est à fusionner avec `shared`
- M2-L08 : valide — +un seul point de décision par sous-arbre ; ordre de sortie prévisible / −enfant ajouté pendant la sortie non réglé / conflits: M5-L07, M4-L09, M3-L10, M2-L10 / cohérence: ok (`stagger` en token, `disappear`, handle §8.0 #4) ; présence à la racine, déjà décidée dans M5-L07
- M2-L09 : valide — +même promesse avec ou sans animation ; état lisible en CSS et par un agent / −attribut absent sans runtime ; écrit par le runtime / conflits: M1-L10, M4-L10, M5-L08, M3-L10 / cohérence: exception: attribut moteur, identique à M5-L08 ; `finished` au même tick en réduit reste conforme à §8.0 #4
- M2-L10 : valide — +les frères ne sautent pas ; même mécanisme que le réordonnancement / −chevauchement du sortant ; test visuel obligatoire / conflits: M1-L09, M4-L09 (sur place, contraire) / cohérence: exception: option `data-motion-exit="pop"` qui modifie la géométrie du flux ; à inscrire dans la table de M5-L09

## Doublons à fusionner

Chaque groupe indique l'id à garder ; les autres ids sont absorbés (leurs apports listés).

- D1 État non géométrique : garder M5-L03 ; absorbent M2-L03 (`@property`), M3-L06 (vitesse estimée), M4-L03 (ressort en jeton). M1-L05 est une primitive de reprise à intégrer comme source de vitesse, non un doublon.
- D2 Géométrie avant mutation : garder M4-L01 ; absorbent M2-L01 (lecture réelle quand elle existe), M3-L02 (portée bornée à la racine).
- D3 Primitive et point de capture : garder M5-L01 ; absorbent M1-L01 (`mutate` = transaction), M1-L02 (ordre par environnement, Angular à corriger), M3-L03 (chemins par environnement).
- D4 Détection CSS seul / survol : garder M5-L02 ; absorbent M2-L02 (pont en diagnostic), M3-L04 (sonde opt-in). À trancher avant fusion : qui écrit `data-hover` (M1-L03 : moteur ; M4-L02 : auteur).
- D5 Panneau monté : garder M5-L04 ; absorbent M2-L04, M4-L04, M3-L07 ; M1-L06 devient la mécanique native (grid 0fr → 1fr) de ce preset, à condition de retirer son « pas de verbe ».
- D6 Élément partagé : garder M5-L05 ; absorbent M2-L05 (registre), M3-L08 (unicité par document), M4-L05 (unicité à la capture). M1-L07 (valeur libre) est écarté. M2-L06 et M4-L05 restent en conflit sur `match-element`.
- D7 Navigation et transitions de page : garder M4-L07 ; absorbent M1-L08 (cross-document natif), M5-L06 (`shared` sur le conteneur), M2-L07 (intégration sans verbe, option à renommer), M4-L08 (sous-cas Astro et MPA), M3-L09 (outlet observé).
- D8 Sortie d'un sous-arbre : garder M5-L07 ; absorbent M2-L08 (enfants en stagger), M3-L10 (sortie sur la racine), M4-L09 (statut `inherited`) — hors « sur place ».
- D9 Sortie en liste : garder M2-L10 ; absorbe M1-L09 (indexation sans sortants). Conflit avec M4-L09 à trancher.
- D10 Attribut de présence : garder M5-L08 ; absorbent M2-L09 (même tick en réduit), M1-L10 (`finished` sur le sous-arbre), M4-L10 (SSR = `present`), M3-L10 (sortie racine ; nom à renommer en `data-presence`).

## Points transverses

- `data-motion="layout"` (M2-L05, M4-L01, M4-L04, M4-L05, M2-L04) : un verbe en valeur, contraire à §8.1 #1 (`data-motion` nomme une animation ou une définition). À remplacer par `defineMotion(…, { verb: 'layout' })` (M5-L01).
- Noms d'attributs : `data-presence` (M1-L10, M2-L09, M4-L10, M5-L08) contre `data-motion-presence` (M3-L10, M4-L04 pour l'option `keep`) ; valeurs `exiting` contre `leaving`. Trancher une seule fois.
- Pré-mutation Angular : M1-L02, M2-L01, M3-L03, M4-L01 et M5-L01 citent quatre hooks différents ; un seul spike doit trancher.
- Reprise par défaut de `emphasize` : §8.0 bis #4 (`carry` pour un changement d'état) contre R12 (`restart`) ; M2-L03 et M5-L03 tranchent différemment.
- Observation des classes (M4-L02) contre attributs seuls (§8.0 bis, M3-L01) : à arbitrer par le greffier.
