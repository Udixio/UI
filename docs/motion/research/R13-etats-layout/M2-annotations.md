# R13 — Annotations de M2 (layout, partagé, présence) sur M1, M3, M4, M5

Légende : valide / conteste / neutre. Cohérence jugée contre §8.0, §8.0 bis, §8.1 et §4.3 du spec.

## M1

- M1-L01 : valide — +une passe de lecture et d'écriture pour tous les environnements / −mutation synchrone requise ; changement asynchrone non couvert sans M1-L02 / conflits: M1-L02, M5-L01 / cohérence: exception: forme noyau `motion.layout(portée, mutation)` nouvelle, justifiée pour les mutations sans attribut
- M1-L02 : conteste — +Svelte `$effect.pre` est un vrai point pré-mutation / −Angular `afterRender` s'exécute après la mise à jour du DOM, donc `EarlyRead` ne capture pas le « avant » ; le store est faux si la page bouge / conflits: M3-L03, M4-L01 / cohérence: exception: mécanique divergente par adaptateur, déclarée et masquée par la surface `layout`
- M1-L03 : conteste — +`:hover` devient observable sans polling / −double source (CSS `hover:` et `data-hover` écrit par le moteur) ; `pointerover` ≠ `:hover` au tactile ; contredit §4.3 / conflits: M3-L04, M4-L02 / cohérence: exception: attribut d'état écrit par le moteur, non prévu par §8.0 bis
- M1-L04 : conteste — +une seule primitive « avant, après, reprise » ; pas de huitième verbe / −`layout` devient impropre pour une couleur (risque C5) ; rompt « un verbe = une forme de mouvement » / conflits: M2-L03, M3-L06, M4-L03, M5-L03 / cohérence: exception: déclarée par M1 ; inutile, `emphasize` couvre déjà ce cas
- M1-L05 : valide — +ressort analytique donne une vitesse exacte en `carry`, sans saut / −solution analytique seulement pour un ressort linéaire à un degré de liberté ; bascule natif vers JS en cours de mouvement / conflits: M3-L06, M5-L03 / cohérence: ok (`velocity.source` §8.0 bis #4, tokens R12)
- M1-L06 : valide — +hauteur `auto` par `grid-template-rows` 0fr vers 1fr, sans JS et sans `interpolate-size` ; panneau monté / −contenu fermé reste dans l'arbre sans `inert` ; `hidden="until-found"` non vérifié / conflits: M2-L04, M3-L07, M4-L04, M5-L04 / cohérence: exception: CSS pur hors grammaire `data-motion`, à déclarer ; sinon ok
- M1-L07 : conteste — +nœud sortant gardé jusqu'à `finished` (conforme §8.0 #2) / −`data-motion-layout-id` : nom d'attribut différent de `data-motion-shared`, valeur libre (contraire §8.0 bis, référence seule) / conflits: M2-L05, M3-L08, M4-L05, M5-L05 / cohérence: exception: nom et valeur divergents, à remplacer par `data-motion-shared`
- M1-L08 : valide — +une mécanique pour routeurs et Astro ; cross-document natif, pas de sortie JS / −une transition document-scopée chasse la précédente ; Firefox sans cross-document / conflits: M3-L09, M4-L07, M5-L06 / cohérence: ok (action, pas verbe, R12 M3-V03 ; `@view-transition` générée par le plugin, C14)
- M1-L09 : valide — +sorties hors flux, frères en FLIP immédiat, ordre d'entrée visible / −`position: absolute` casse largeur et grille du sortant ; `sibling-index()` compte les sortants / conflits: M2-L10, M4-L09 / cohérence: exception: `stagger` compté sans sortants et sortie de liste hors défaut de `disappear`, à inscrire au manifeste
- M1-L10 : valide — +`getAnimations({ subtree: true })` attend le sous-arbre sans dépendre de `transitionend` ; `data-presence` lisible en CSS / −le garde-fou temporel masque une animation bloquée ; `getAnimations` force un recalcul / conflits: M3-L10, M4-L10, M5-L08, M4-L09 / cohérence: exception: attribut écrit par le moteur (§4.3), même exception que M5-L08

## M3

- M3-L01 : valide — +déclencheur = attribut, Tailwind traduit sans bruit de classes ; coût borné à la racine / −liste d'attributs à tenir au manifeste ; l'attribut duplique la classe / conflits: — / cohérence: exception: `data-open` sans préfixe (état auteur) et `data-motion-scope` nouveau, à inscrire
- M3-L02 : valide — +une source de vérité pour tous les environnements ; lecture groupée en frame unique / −valeur périmée si un déplacement hors racine n'est pas observé ; coût de lecture par élément suivi / conflits: M2-L01, M4-L01, M1-L02 / cohérence: ok (frame unique §8.0 #3, aucun verbe nouveau)
- M3-L03 : neutre — +écriture exacte quand elle passe par `udixio.motion.set` / −`set` est une forme nouvelle ; `ngDoCheck` ne garantit pas que le DOM de l'hôte n'est pas encore mis à jour (à vérifier) / conflits: M1-L01, M1-L02 / cohérence: exception: `udixio.motion.set` hors surface §8.0 bis #3, à documenter comme exception
- M3-L04 : valide — +zéro écouteur par défaut ; sonde opt-in ; cohérent avec §4.3 / −un `hover:` qui déplace un élément n'a jamais de FLIP sans attribut ; double source ; les bugs cités sont à vérifier / conflits: M1-L03 / cohérence: ok (§4.3 ; la sonde n'a pas de forme grammaticale)
- M3-L05 : valide — +identique en HTML et frameworks, sans clé lue, via `removedNodes` / `addedNodes` d'un même lot / −nœud recréé non reconnu comme déplacé ; dépend de la coalescence des lots / conflits: M3-L02 / cohérence: ok (`layout`, `appear`, aucune option)
- M3-L06 : valide — +`emphasize` avec `trigger="state"` sans verbe nouveau ; reprise `carry` / −vitesse estimée sur deux frames, bruitée ; `emphasize` mêle états et attention / conflits: M1-L04, M4-L03, M5-L03 / cohérence: ok (`trigger` listé §4.1, `carry` §8.0 #4)
- M3-L07 : valide — +mesure la seule cible ; origine = tween courant, aucune lecture pré-mutation ; interruption propre / −un `hidden` ou `display: none` immédiat casse la mesure ; `interpolate-size` absent de Firefox et Safari / conflits: M1-L06, M4-L04, M5-L04 / cohérence: exception: cas particulier de `layout` (cible lue, origine tween), à documenter
- M3-L08 : valide — +registre unique par document dans le runtime global ; erreur dev visible / −clé dupliquée silencieuse en prod ; collisions entre îles indépendantes / conflits: M2-L05 (prod : premier inscrit ici, dernier monté là-bas), M4-L05, M5-L05, M1-L07 / cohérence: ok (§8.0 #1, grammaire `data-motion-<option>`)
- M3-L09 : neutre — +natif d'abord, aucun adaptateur de routeur, observation d'un seul outlet / −Firefox sans cross-document, repli à définir ; comportement Astro à vérifier ; un routeur qui réécrit le conteneur casse l'observation / conflits: M1-L08, M4-L07, M5-L06 / cohérence: exception: nouvel attribut `data-motion-outlet`, justifié par la portée bornée, à inscrire
- M3-L10 : valide — +une règle de sortie pour quatre environnements ; index DOM conservé, retrait différé sans observateur sur le document / −en HTML pur, un `remove()` nu détruit l'effet ; retenir un nœud retiré en React reste à gérer / conflits: M1-L10, M4-L10, M5-L08, M4-L04 / cohérence: exception: `data-motion-presence` et valeur `leaving`, différents de `data-presence` / `exiting` des autres choix ; à unifier

## M4

- M4-L01 : valide — +une règle « avant = dernière géométrie stable » pour quatre environnements ; pas de lecture forcée dans le rendu React / −cache approximatif faute de `getSnapshotBeforeUpdate` pour les fonctions ; cache périmé si un changement CSS échappe au runtime ; React concurrent à tester / conflits: M2-L01, M3-L02, M1-L02 / cohérence: ok (`layout`, §8.1 #2 ; cache justifié)
- M4-L02 : valide — +pas de polling ; lint de build qui signale `justify-*` sous `hover:` ; erreur au build (C5) / −MutationObserver arrive après mutation ; `pointerenter` absent au tactile sans `pointerdown` / conflits: M1-L03 (qui écrit `data-hover` : l'auteur ici, le moteur là) / cohérence: ok (§8.0 bis #1, règle de build seulement)
- M4-L03 : valide — +aucun verbe ajouté ; `easing="spring-<nom>"` est un jeton ; même grammaire qu'un `hover:` Tailwind / −couleur non déclarée en `@property` ne s'interpole pas ; préfixe `spring-` à réserver / conflits: M4-L02, M1-L04 / cohérence: ok (`trigger="state"` est déjà listé §4.1, donc pas une nouveauté contrairement à ce que dit le choix)
- M4-L04 : conteste — +une règle pour accordéon et disclosure ; `inert` immédiat ; `<details>` natif en premier / −`data-motion-presence="keep"` entre en collision avec l'attribut d'état de M3-L10 ; `hidden="until-found"` et `::details-content` non couverts par R1 / conflits: M3-L10, M5-L04, M1-L06 / cohérence: exception: option `presence="keep"` nouvelle ; à renommer
- M4-L05 : conteste — +même nom en HTML, React, Angular, Svelte et Astro ; une seule règle d'unicité / −double rendu (`match-element` si disponible, registre sinon) : contraire à la fidélité §4.7 et à M2-L06 ; `match-element` non Baseline / conflits: M2-L06, M3-L08, M5-L05, M1-L07 / cohérence: exception: rendu différent selon le navigateur (§4.7) ; la grammaire est ok
- M4-L06 : valide — +pas d'élément fantôme ; comportement prévisible pour les îles hydratées à des moments différents (C6) / −une frame n'est pas une garantie d'hydratation ; `client:visible` non couvert ; un sortant retenu gonfle le DOM / conflits: M4-L09, M4-L08 / cohérence: exception: fenêtre globale, réglage du manifeste et non option de verbe
- M4-L07 : valide — +une API pour quatre intégrations ; `direction` est une option existante ; repli propre / −same-document seulement ; points d'extension des routeurs et `addTransitionType` à vérifier / conflits: M1-L08, M5-L06, M4-L08 / cohérence: exception: preset `route` en plus des dix de §8.1 #4, à inscrire au manifeste
- M4-L08 : valide — +deux chemins natifs sans JS là où ils existent (C3) ; `transition:persist` garde l'île et son handle / −`ClientRouter` rejoue les scripts ; noms d'événements Astro 5.x et présence du composant selon la version (R2) à vérifier / conflits: M4-L07, M1-L08, M3-L09 / cohérence: exception: usage natif `transition:name` documenté comme non portable (déclaré)
- M4-L09 : conteste — +règle unique « la sortie la plus haute décide » ; pas de fantôme dans une liste réordonnée / −contredit M5-L07 : M5 anime chaque enfant avec `stagger`, M4 fait sortir les enfants en statut `inherited` ; comportement Svelte (`out:` local, `|global`) à vérifier / conflits: M5-L07, M1-L10, M3-L10, M2-L08 / cohérence: exception: statut `inherited` nouveau au handle, non prévu par §8.0 #4
- M4-L10 : valide — +état de présence lisible par variants et `inspect()` ; SSR sans état de sortie, pas de flash à l'hydratation / −un `MutationObserver` par changement ; le fondu réduit reste une animation / conflits: M1-L10, M5-L08, M4-L09 / cohérence: exception: attribut écrit par le runtime (déclaré) ; valeur `exiting` à unifier avec `leaving` de M5-L08

- M5-L02 : valide — +transforme l'erreur la plus probable en erreur visible, avec renvoi à une recette / −ne voit pas les classes dynamiques ni un `:hover` écrit dans une feuille à la main ; faux positifs possibles / conflits: M4-L02, M1-L03 / cohérence: exception: règle croisée verbe × variante, déclarée ; `emphasize` autorisé à `hover:`

## Doublons à fusionner

- Présence, attribut d'état de sortie : M2-L09, M1-L10, M3-L10, M4-L10, M5-L08 → garder M5-L08 (contrat fermé et lint) ; reprendre le mécanisme de M1-L10 ; trancher `leaving` ou `exiting` et `data-presence` ou `data-motion-presence`
- Panneau monté : M2-L04, M1-L06, M3-L07, M4-L04, M5-L04 → garder M5-L04 ; mécanique CSS de M1-L06 ; retirer `presence="keep"` de M4-L04
- Changement d'état non géométrique : M2-L03, M3-L06, M4-L03, M5-L03 → garder M5-L03 (M1-L04 est un conflit, pas un doublon)
- Survol et pseudo-classes : M4-L02, M5-L02, M2-L02 → garder M5-L02 ; fusionner la détection de M4-L02
- Mesure « avant » : M3-L02, M4-L01, M2-L01 → garder M3-L02 ; M4-L01 pour les points par environnement ; M2-L01 est un doublon de M4-L01 et doit être retiré
- Point pré-mutation (API) : M1-L01, M5-L01, M3-L03 → garder M1-L01 ; M5-L01 apporte la surface ; retirer `udixio.motion.set` de M3-L03 si M1-L01 est retenu
- Identité partagée : M5-L05, M3-L08, M4-L05, M2-L05, M1-L07 → garder M5-L05 ; M3-L08 pour le registre ; retirer `data-motion-layout-id` de M1-L07 ; M2-L05 est un doublon de M5-L05
- Navigation de page : M4-L07, M1-L08, M5-L06, M2-L07 → garder M4-L07 (routeurs, `direction`) ; M2-L07 est un doublon ; M3-L09 reste une alternative à trancher
- Présence de sous-arbre : M5-L07, M2-L08, M3-L10 → garder M5-L07 ; M2-L08 est un doublon ; M3-L10 apporte les hooks par environnement
- Sortie de liste hors flux : M1-L09, M2-L10 → garder M1-L09 ; M2-L10 est un doublon
