# M5 — Annotations des choix M1 à M4 (R13)

Grille de cohérence (§8 de la spec) : verbes fermés `appear`, `disappear`, `emphasize`, `reveal`, `scrub`, `loop`, `layout` ; `data-motion` = référence seule, verbe jamais écrit en HTML (M5-V04) ; options `data-motion-<option>` dans la liste fermée de M5-V03 ; noms réservés `enter`, `exit`, `in`, `out`, `transition`, `animate`, `initial`, `old`, `new`, `view-transition-*`, `AnimatePresence` (M5-V07).

## Annotations

- M1-L01 : valide — + le point d'écriture unique est le bon endroit pour la mesure « avant » / « après » / « jeu » · − trois points d'écriture pré-mutation coexistent (M1-L01, M3-L03, M5-L01) · conflits: M3-L03, M5-L01 · cohérence: ok (`motion.layout` est une fonction, pas un attribut)
- M1-L02 : neutre — + liste utile des points de capture par framework · − fusionné dans M3-L03 · conflits: M3-L03 · cohérence: ok
- M1-L03 : conteste — + `:hover` devient observable sans polling · − l'état `data-hover` / `data-focus` est écrit par le moteur, troisième attribut de ce type, contraire à §8.0 bis (Tailwind règle les états) · conflits: M5-L02, M4-L02, M3-L04, M2-L02 · cohérence: exception: attributs d'état écrits par le moteur, non déclarés au manifeste
- M1-L04 : conteste — + la table cible → mécanique rend le choix natif / JS lisible · − `layout` devient le verbe de tout changement d'état, en contradiction avec le sens défini en R12 (mise en page, élément partagé) et avec M3-L06, M4-L03, M5-L03 · conflits: M3-L06, M4-L03, M2-L03, M5-L03, M5-V01 · cohérence: exception: `layout` sans géométrie
- M1-L05 : valide — + un ressort de token ne doit pas être réduit à `linear()` s'il peut être interrompu · − contredit M5-S05 (ressort de token compilé en `linear()` au build) : l'émission des tokens doit garder les paramètres · conflits: M5-S05, M3-L06 · cohérence: ok (`carry`, `velocity.source`)
- M1-L06 : valide — + `grid-template-rows` 0fr → 1fr donne une hauteur `auto` sans JS, cohérent avec C3 (à vérifier contre R1) · − sort de la grammaire : pas de verbe, pas de `data-motion`, repli `restart` au lieu de `carry` (V02) · conflits: M2-L04, M3-L07, M4-L04, M5-L04 · cohérence: exception: pas de verbe, défaut `restart`
- M1-L07 : conteste — + identité tenue par le registre global, comme les autres propositions · − `data-motion-layout-id="<id>"` est une valeur libre, contraire à « référence seule » (§8.0 bis) ; option hors liste V03 ; doublon de `data-motion-shared` · conflits: M3-L08, M2-L05, M4-L05, M5-L05 · cohérence: exception: valeur libre, option `layout-id` hors liste
- M1-L08 : neutre — + la règle « une transition de document chasse la précédente » est utile · − fusionné dans M4-L07 · conflits: M4-L07, M5-L06, M3-L09 · cohérence: ok (`motion.navigate` est une action, `@view-transition` émis par le plugin)
- M1-L09 : valide — + le délai d'entrée suit l'indice visible, donc un sortant ne crée pas de trou dans le stagger · − écart à `sibling-index()` à inscrire au manifeste · conflits: M4-L09, M2-L10 · cohérence: exception: sortie hors flux dans une liste, indice compté hors sortants
- M1-L10 : valide — + `getAnimations({ subtree: true })` évite le piège de `transitionend` qui ne part pas si rien ne change · − valeur `exiting` à trancher contre `leaving` (M5-L08) ; le garde-fou temporel doit émettre un avertissement dev, sinon il masque une sortie bloquée · conflits: M2-L09, M4-L10, M5-L08, M3-L10 · cohérence: exception: attribut écrit par le moteur, sans préfixe d'option
- M2-L01 : neutre — + `getSnapshotBeforeUpdate` donne la lecture exacte sur les classes · − impose un wrapper classe interne sur chaque composant, coût d'API caché · conflits: M4-L01, M3-L02, M1-L02 · cohérence: ok
- M2-L02 : valide — + une erreur de build sur une combinaison verbe / déclencheur est exactement la garde M5-S10 · − le pont `@property` + `allow-discrete` est fragile (R4), ne pas le proposer comme chemin par défaut · conflits: M1-L03, M3-L04, M4-L02, M5-L02 · cohérence: ok (à inscrire au manifeste)
- M2-L03 : neutre — + `@property` rend la valeur animable par variable, sans JS quand la cible est compositable · − toute valeur non déclarée saute sans transition, un lint doit la vérifier · conflits: M1-L04, M3-L06, M4-L03, M5-L03 · cohérence: exception mineure: variable animée hors espace `--udx-motion-*` (M5-V07)
- M2-L04 : valide — + un seul verbe `layout` pour accordéon et disclosure, ce qui suit M5-L04 si `collapse` change de verbe · − `inert` avant `finished` est une exception à « retenu jusqu'à `finished` », à déclarer · conflits: M5-L04, M1-L06, M3-L07, M4-L04 · cohérence: exception: `inert` posé avant la fin de l'animation (déclarée)
- M2-L05 : conteste — + le registre `globalThis` partage la clé entre îles sans contexte · − clé libre (texte), contraire à « référence seule » ; `data-motion="layout"` écrit le verbe en HTML · conflits: M3-L08, M4-L05, M5-L05, M1-L07 · cohérence: exception: verbe écrit en HTML, clé libre
- M2-L06 : conteste — + un seul rendu à tester, cohérent avec la frame unique · − contredit C3 et §4.5 sans démonstration ; le FLIP JS n'a pas de snapshot, sa fidélité à la VT ne se compare que par spike · conflits: M4-L05, M1-L07 · cohérence: exception: C3 et §4.5 (déclarée par M2)
- M2-L07 : conteste — + liste claire des intégrations Astro, SvelteKit, Angular et React, utile pour M4-L07 · − `data-motion-transition` : `transition` est un nom réservé (M5-V07) ; une option sans verbe pour une navigation · conflits: M4-L08, M1-L08, M4-L07, M5-L06 · cohérence: exception: nom réservé
- M2-L08 : valide — + une seule règle « racine seule » couvre aussi M5-L07 et M3-L10 · − `order` pour la sortie inverse absent de V03 ; `out:` Svelte reste natif et non exposé, à garder hors grammaire · conflits: M5-L07, M3-L10 · cohérence: ok (enfants sans attribut, `stagger` token)
- M2-L09 : valide — + `finished` résolu au même tick en rendu réduit garde la forme de l'API, bon contrat · − `exiting` ou `leaving` : une seule valeur à retenir ; attribut écrit par le runtime, à déclarer · conflits: M1-L10, M4-L10, M5-L08, M3-L10 · cohérence: exception: attribut écrit par le runtime (déclarée)
- M2-L10 : conteste — + le popLayout est la bonne géométrie pour la sortie hors flux · − `data-motion-exit="pop"` : `exit` est un nom réservé (M5-V07) ; redondant avec M1-L09, qui n'exige aucune option · conflits: M1-L09 · cohérence: exception: nom réservé, option hors V03
- M3-L01 : valide — + `attributeFilter` borné par racine, coût proportionnel aux racines suivies · − `data-open` non préfixé est un état d'auteur, exception à déclarer ; `data-motion-scope` à ajouter à V03 · conflits: M4-L02, M3-L02 · cohérence: exception: `data-open` non préfixé, `data-motion-scope` nouvelle option
- M3-L02 : valide — + lecture groupée dans la frame unique, un seul cache pour L03, L05, L08 et L10 · − lecture par élément suivi, coût à mesurer avant de figer le budget · conflits: M4-L01, M2-L01 · cohérence: ok (frame unique, aucun verbe ni option)
- M3-L03 : conteste — + capture en phase capture sur le document, utile pour les interactions utilisateur · − troisième point d'écriture pré-mutation (`udixio.motion.set`) après `motion.layout` et `mutate`, contraire à « une seule façon d'écrire » ; `pointerdown` ne couvre pas un changement programmé · conflits: M1-L01, M5-L01, M1-L02 · cohérence: exception: fonction `udixio.motion.set` nouvelle
- M3-L04 : valide — + la sonde `@property` opt-in limite le coût aux cas demandés, bugs navigateurs documentés · − reprend §4.3 et duplique M4-L02 · conflits: M1-L03, M4-L02 · cohérence: ok (aucun verbe, aucune option)
- M3-L05 : valide — + identique dans les quatre frameworks, aucune clé à maintenir, complète L02 · − un nœud recréé n'est pas reconnu comme déplacé, à préciser au manifeste · conflits: aucun (dépend de M3-L02) · cohérence: ok (`layout` avec `carry`, `appear`)
- M3-L06 : valide — + `trigger="state"` est déjà dans la liste V03 ; c'est la forme à garder pour les quatre états non géométriques · − `emphasize` mêle états et attention (R12), à scinder si besoin · conflits: M1-L04, M1-L05 · cohérence: ok
- M3-L07 : neutre — + mesure de la seule cible, évite la lecture pré-mutation · − fusionné dans M2-L04 · conflits: M2-L04, M4-L04, M1-L06 · cohérence: exception: cas particulier de `layout` (lecture de la cible)
- M3-L08 : valide — + l'option `data-motion-shared` respecte V04 ; à compléter par `defineShared` (M5-L05) pour rendre la clé vérifiable · − clé dupliquée silencieuse en production, lint impossible pour des clés construites à l'exécution · conflits: M1-L07, M2-L05, M4-L05, M5-L05 · cohérence: ok
- M3-L09 : conteste — + `pageswap` / `pagereveal` donnent un chemin cross-document natif sans JS · − côté SPA, un MutationObserver arrive après la mutation, donc trop tard pour capturer l'ancien état que `startViewTransition` doit encadrer ; `data-motion-outlet` hors V03 · conflits: M4-L07, M4-L08, M1-L08 · cohérence: exception: option `data-motion-outlet` hors liste
- M3-L10 : valide — + `udixio.motion.remove(el)` est le seul moyen HTML pur de retenir un nœud, à garder · − `data-motion-presence` est un état nommé comme une option ; `leaving` contre `exiting` · conflits: M2-L09, M4-L10, M5-L08, M2-L08 · cohérence: exception: état nommé `data-motion-presence` (devrait être `data-presence`)
- M4-L01 : neutre — + la capture Svelte (`$effect.pre`) et Angular (`afterRenderEffect`) est cohérente avec M3-L03 · − `data-motion="layout"` écrit le verbe en HTML ; la lecture Angular dans un gestionnaire d'événement rate les changements de signal non événementiels · conflits: M3-L02, M2-L01, M3-L03 · cohérence: exception: verbe écrit en HTML
- M4-L02 : valide — + la règle de lint sur variante de pseudo-classe est la même que M5-L02 · − l'auteur écrit `data-*` via `pointerenter` / `focusin` : coût d'écriture, tactile non couvert · conflits: M1-L03, M3-L04, M2-L02, M5-L02 · cohérence: ok
- M4-L03 : neutre — + `easing="spring-<nom>"` reste un token (V03), le ressort n'est pas une valeur libre · − `data-motion="emphasize"` écrit le verbe en HTML ; préfixe `spring-` à réserver au manifeste · conflits: M1-L04, M3-L06 · cohérence: exception: verbe écrit en HTML
- M4-L04 : conteste — + `<details>` natif comme premier choix est la bonne priorité (C3) · − `data-motion-presence="keep"` : option `presence` hors V03, même famille de nom que l'état `data-presence` ; verbe `layout` écrit en HTML · conflits: M2-L04, M3-L07, M3-L10, M2-L09 · cohérence: exception: option `presence`, verbe écrit en HTML
- M4-L05 : valide — + l'unicité vérifiée à la capture est le bon critère, à inscrire dans le lint · − `match-element` quand il est disponible crée deux chemins de rendu, contraire à M2-L06 ; verbe écrit en HTML · conflits: M2-L06, M1-L07, M3-L08 · cohérence: exception: verbe écrit en HTML (option `shared` cohérente avec M5-V08)
- M4-L06 : valide — + une seule fenêtre de rétention par document, partagée avec la présence de M4-L09 · − « une frame » est un seuil arbitraire, à remplacer par la fin d'hydratation · conflits: M4-L09, M3-L10 · cohérence: ok (`appear` / `disappear`, défauts par verbe)
- M4-L07 : valide — + `navigate` avec `direction` respecte V03 et la correction §8.1 (`start` / `end`) ; regroupe M1-L08 et M5-L06 · − preset `route` sans verbe : V09 exige un verbe par entrée ; `addTransitionType` et `viewTransition` (React Router) à vérifier · conflits: M1-L08, M5-L06, M2-L07, M3-L09, M4-L08 · cohérence: exception: preset `route` sans verbe ; `direction` en `start` / `end` (proposition §8.1, pas V03)

## Doublons à fusionner

- Cache « avant » : garder **M3-L02** ← M4-L01, M2-L01
- Point de capture et d'écriture pré-mutation : garder **M1-L01** ← M1-L02, M3-L03, M5-L01 (un seul point d'écriture)
- Pseudo-classes CSS vers `layout` (lint, pont, contrat) : garder **M4-L02** ← M2-L02, M3-L04, M5-L02 ; M1-L03 reste en conflit
- État non géométrique vers `emphasize` : garder **M3-L06** ← M2-L03, M4-L03, M5-L03 ; M1-L04 reste en conflit
- Panneau monté : garder **M2-L04** ← M1-L06 (base CSS), M3-L07, M4-L04 (sans `presence="keep"`), M5-L04
- Élément partagé : garder **M3-L08** ← M1-L07 (sans `layout-id`), M2-L05, M4-L05, M5-L05 (avec `defineShared`)
- Navigation vers le runtime : garder **M4-L07** ← M1-L08, M5-L06
- Natif cross-document et Astro : garder **M4-L08** ← M2-L07 (sans `data-motion-transition`) ; M3-L09 reste en conflit sur le volet SPA
- Sortie hors flux en liste : garder **M1-L09** ← M2-L10 (sans `data-motion-exit`)
- Présence de sous-arbre, racine retenue : garder **M2-L08** ← M3-L10 (mécanisme `remove`), M5-L07
- Attribut d'état de présence : garder **M2-L09** ← M4-L10, M5-L08 (valeur à trancher) ; M1-L10 reste séparé pour son mécanisme `getAnimations`
