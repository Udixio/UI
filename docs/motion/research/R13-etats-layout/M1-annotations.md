# M1 — Annotations sur les choix M2 à M5 (R13, étape 2)

Jugement contre §8 de la spec : verbes fermés (7), grammaire `data-motion` + `data-motion-<option>`, options partagées, défauts de reprise et de rendu réduit par verbe, handle (`finished` ne rejette jamais), présence (`inert` jusqu'à `finished`), noms réservés, Tailwind pour états et tokens.

## M2 — layout, partagé, présence

- M2-L01 : valide — +cinq environnements ont un chemin de lecture, mesure interne au runtime / −« nœud classe interne » React contredit l'absence de classes (M1-L02) / conflits: M1-L02, M4-L01, M3-L02 / cohérence: ok (`layout`, `duration`, `easing`)
- M2-L02 : valide — +erreur de build pour `hover:` sur `layout`, contrat net avec Tailwind / −pont `@property` fragile (bugs R4) / conflits: M1-L03, M3-L04, M5-L02 / cohérence: ok (état par attribut §8.0 bis ; erreur au manifeste)
- M2-L03 : conteste — +aucun verbe nouveau, `@property` comme unité d'animation, reprise exacte avec anime / −`emphasize` est une mise en avant ponctuelle (R12) : un état persistant lui donne un autre sens ; défaut `carry` ici, `restart` chez M5-L03 / conflits: M1-L04 (verbe `layout` pour cibles non géométriques), M3-L06, M4-L03, M5-L03 / cohérence: exception : pas de `trigger` (le changement d'état sert de déclencheur), contraire à l'option partagée `trigger`
- M2-L04 : valide — +contenu présent pour la recherche et les ancres, accessibilité immédiate / −`interpolate-size` Chromium seul ; `until-found` à vérifier / conflits: M1-L06, M3-L07, M4-L04, M5-L04 / cohérence: exception : `inert` posé avant `finished`, contraire à §8.0 #2 ; justifiée (le nœud ne sort jamais du DOM), à acter au journal
- M2-L05 : valide — +identité sans contexte, attribut interrogeable par les agents / −règle de prod « le dernier monté gagne » contredit M3-L08 (« le premier inscrit garde ») : à trancher / conflits: M1-L07, M3-L08, M4-L05, M5-L05 / cohérence: ok (`data-motion-shared` est une option ; référence seule)
- M2-L06 : conteste — +un seul rendu FLIP à tester, interruptible, sans nom de transition unique / −contredit C3 et §4.5 (natif d'abord) ; le spike de démonstration n'est pas fait / conflits: M4-L05 (`match-element` quand disponible), M1-L07 (alternative native) / cohérence: exception : C3 et §4.5, à consigner au journal si retenue
- M2-L07 : valide — +intégration sans verbe, Astro et routeurs sur une même surface / −`data-motion-transition` nomme l'identité de page alors que M4-L05 et M5-L05 utilisent `data-motion-shared` : deux noms pour un concept / conflits: M1-L08, M3-L09, M4-L07, M4-L08, M5-L06 / cohérence: ok (action non verbe, R12 M3-V03) ; nom d'option à unifier
- M2-L08 : valide — +un seul point de décision par sous-arbre, ordre de sortie prévisible / −enfant ajouté pendant la sortie du parent non réglé / conflits: M1-L10, M3-L10, M4-L09, M5-L07 / cohérence: ok (`stagger` token, `disappear`, handle `finished`) ; présence portée par la racine, règle commune avec M4-L09 et M5-L07
- M2-L09 : valide — +`finished` résolu dans le même tick sous mouvement réduit : le code appelant ne change pas / −nom et valeurs divergent (`exiting` ici et chez M4-L10 ; `leaving` chez M5-L08 ; `data-motion-presence` chez M3-L10) / conflits: M1-L10, M3-L10, M4-L10, M5-L08 / cohérence: exception déclarée : attribut écrit par le runtime, même statut que `data-hover` (M1-L03), à justifier au greffier
- M2-L10 : valide — +les frères ne sautent pas pendant la sortie, même mécanisme que le réordonnancement / −`data-motion-exit="pop"` change le défaut de `disappear` dans une liste ; le nœud sorti casse les grilles / conflits: M1-L09, M3-L10 (index DOM), M4-L09 (« sortie sur place » ambigu) / cohérence: exception : défaut de `disappear` modifié en liste ; à inscrire au manifeste

## M3 — détection, layout, états, présence

- M3-L01 : valide — +coût proportionnel aux racines suivies, même signal dans les quatre environnements / −l'attribut duplique l'état de la classe ; liste `attributeFilter` à maintenir / conflits: M1-L03, M4-L02, M5-L01 / cohérence: exception : `data-open` non préfixé et `data-motion-scope` nouveau ; à inscrire au manifeste
- M3-L02 : valide — +source de vérité unique pour les quatre environnements, lecture groupée dans la frame unique / −valeur périmée si un élément sort de la racine sans mutation observée / conflits: M1-L02, M2-L01, M4-L01 (doublon, à garder) / cohérence: ok (§8.0 #3 : lecture puis écriture)
- M3-L03 : conteste — +raffinement exact pour HTML pur quand l'écriture passe par l'API / −`udixio.motion.set` est un troisième point pré-mutation (avec M1-L01 et M5-L01) ; la capture globale `pointerdown` est fragile / conflits: M1-L01, M5-L01 (doublon, à garder) / cohérence: exception : une entrée de surface en plus de `motion(el, spec)` (§8.0 bis #3)
- M3-L04 : valide — +zéro écouteur par défaut, cohérent avec §4.3 / −un `hover:` qui déplace un élément n'est jamais en FLIP sans attribut / conflits: M1-L03, M2-L02, M5-L02 (mécanisme à garder) / cohérence: ok (§4.3, attribut d'état de L01) ; la sonde `@property` est opt-in, hors grammaire
- M3-L05 : valide — +identique dans les cinq formes, sans clé de framework / −un nœud recréé n'est pas reconnu comme déplacé ; dépend du découpage en lots / conflits: M1-L09, M2-L10 / cohérence: ok (`layout`, `appear`)
- M3-L06 : valide — +aucun verbe nouveau ; reprise `carry` avec vitesse estimée / −`emphasize` mêle états et attention (à scinder) ; vitesse bruitée sur deux frames / conflits: M2-L03, M4-L03, M5-L03 (doublon, à garder), M1-L05 / cohérence: ok (`trigger` listé §4.1, `velocity.source` §8.0 bis #4)
- M3-L07 : valide — +pas de « avant » à mesurer quand l'origine est connue ; `details` et `div` traités pareil / −`display` retiré à `finished` casse la mesure si `hidden` est posé tout de suite / conflits: M2-L04, M4-L04, M5-L04 (doublon, à garder), M1-L06 / cohérence: ok (`layout`, `carry`, `inert`) ; lecture de la cible à documenter comme cas particulier
- M3-L08 : valide — +écriture unique entre îles, clé dupliquée visible en dev / −clé dupliquée silencieuse en prod ; « premier inscrit » contraire à M2-L05 / conflits: M2-L05, M4-L05, M5-L05 (doublon, à garder), M1-L07 / cohérence: ok (grammaire `data-motion-<option>`, registre §8.0 #1)
- M3-L09 : conteste — +aucun adaptateur de routeur requis ; `pageswap` / `pagereveal` natifs / −un MutationObserver arrive après la mutation : trop tard pour capturer l'ancien état d'une View Transition ; seul un fondu d'entrée reste possible / conflits: M1-L08, M4-L07, M4-L08, M5-L06 / cohérence: exception : `data-motion-outlet` nouveau (même justification que `data-motion-scope`) ; à retirer ou réduire à l'arrivée
- M3-L10 : valide — +une règle pour quatre environnements, retrait différé sans observateur sur le document / −`data-motion-presence` ressemble à une option et porte une valeur d'état : contradiction avec la grammaire ; `remove(el)` ajoute une entrée de surface (cf. M3-L03) / conflits: M2-L08, M4-L09, M5-L07, M1-L10, M2-L10 (index DOM contre sortie hors flux) / cohérence: exception : attribut d'état sous un nom d'option ; à renommer en `data-presence` (cadre)

## M4 — intégration frameworks, îles, SSR

- M4-L01 : valide — +une règle « avant = dernière géométrie stable » pour quatre environnements / −cache approximatif hors `getSnapshotBeforeUpdate` ; React concurrent à tester / conflits: M1-L02, M2-L01, M3-L02 (doublon) / cohérence: ok (`data-motion="layout"`) ; cache par élément justifié
- M4-L02 : valide — +pas de polling, erreur de build conforme à C5 / −lint sur classes Tailwind heuristique / conflits: M2-L02, M3-L04, M5-L02 (doublon) / cohérence: ok (manifeste, §8.0 bis #1)
- M4-L03 : conteste — +les 7 verbes conservés, ressort en jeton / −deux syntaxes de ressort : `easing="spring-<nom>"` ici, `spring: 'soft'` chez M5-L03 (et M5-S05) ; valeur `trigger="state"` à documenter / conflits: M5-L03, M3-L06, M2-L03 (doublon), M5-S05 / cohérence: exception : `easing` accepte un ressort, alors que le ressort est une option distincte chez M5 ; à arbitrer
- M4-L04 : conteste — +une règle pour accordéon et disclosure, aucun `display:none` pendant l'animation / −`presence="keep"` (`data-motion-presence="keep"`) entre en collision avec l'attribut d'état `data-motion-presence` de M3-L10 ; `layout` seul ne suffit pas, c'est M5-L04 / conflits: M5-L04, M2-L04, M3-L07 (doublon), M3-L10 (collision de nom) / cohérence: exception : option `presence` nouvelle, nom à changer
- M4-L05 : valide — +même nom dans cinq environnements, une seule règle d'unicité / −`match-element` quand il est disponible donne un rendu différent du FLIP (M2-L06) : pas de rendu unique / conflits: M2-L06, M5-L05 (doublon), M3-L08 (doublon) / cohérence: ok (option `shared`, `layout`) ; `view-transition-*` reste réservé côté auteur
- M4-L06 : valide — +pas d'élément fantôme, prévisible pour les îles hydratées à des moments différents / −une frame n'est pas une garantie d'hydratation ; `client:visible` non couvert / conflits: M4-L09 (délai partagé), M2-L05, M3-L08 / cohérence: exception : fenêtre de rétention globale, hors défauts par verbe ; à inscrire au manifeste
- M4-L07 : valide — +une API pour quatre intégrations, `direction` existant / −signature `navigate(run, { direction })` différente de `motion.navigate(update)` (M5-L06) ; `run` doit résoudre au montage / conflits: M5-L06 (doublon), M1-L08, M2-L07, M3-L09 / cohérence: ok (`direction`, handle §8.0 #4) ; preset `route` sans verbe, comme R12 M3-V03
- M4-L08 : valide — +deux chemins natifs sans JS là où ils existent (C3) / −`<ClientRouter />` remplace le routage natif et rejoue les scripts ; noms d'événements Astro à vérifier / conflits: M4-L06, M4-L07, M2-L07, M3-L09 / cohérence: exception déclarée : `transition:name` natif hors grammaire (non portable) ; acceptable si documenté
- M4-L09 : valide — +une règle « la sortie la plus haute décide » ; pas de fantôme dans une liste réordonnée / −statut `inherited` ajouté au handle, hors de la forme fermée de §8.0 #4 ; « garde sa position » est ambigu avec M2-L10 / conflits: M2-L10, M3-L10, M5-L07, M4-L06 / cohérence: exception : statut `inherited` ; à inscrire dans §8.0 #4 ou retirer
- M4-L10 : valide — +état lisible en CSS et par `inspect()`, pas de flash à l'hydratation (SSR toujours `present`) / −la valeur `exiting` diffère de `leaving` (M5-L08, M3-L10) ; le fondu réduit rejoint M2-L09 / conflits: M2-L09, M5-L08 (doublon), M1-L10, M3-L10 / cohérence: exception : attribut posé par le runtime (même statut que `data-hover`), à justifier au greffier

## M5 — API, DX, outillage

- M5-L01 : valide — +un point d'écriture pour cinq formes, HTML pur couvert, l'auteur ne déclare ni mesure ni FLIP / −React sans point pré-mutation public (tranché par M4) ; Angular à confirmer / conflits: M1-L01, M3-L03 (doublon) ; M1-L02, M2-L01, M4-L01 pour la capture / cohérence: ok (V01, V02, V04, S04) ; `state` et `mutate` justifiés
- M5-L02 : valide — +l'erreur la plus probable (animer un survol en `layout`) devient visible / −classes dynamiques et CSS écrit à la main non couverts / conflits: M2-L02, M4-L02 (doublon), M3-L04 (mécanisme) / cohérence: ok (S10, V10) ; exception déclarée : `emphasize` accepte `hover:`
- M5-L03 : conteste — +`emphasize` avec reprise écrite, même forme pour rotation et couleur / −`emphasize` déclaré `restart` par défaut ici, `carry` chez M2-L03, M3-L06, M4-L03 : désaccord de défaut ; option `interrupt` absente de la liste des options partagées / conflits: M2-L03, M3-L06, M4-L03 (doublon, à garder), M1-L04 (verbe), M5-S08 / cohérence: exception : défaut de reprise de `emphasize` à fixer par verbe (§8.0 bis #4) ; nom d'option `interrupt` hors liste partagée
- M5-L04 : valide — +un seul preset pour la hauteur `auto`, pas de `display:none` / −change le verbe de `collapse` (V05) ; deux sources de vérité si l'auteur ajoute `hidden` / conflits: M1-L06, M2-L04, M3-L07, M4-L04 (doublon) / cohérence: exception déclarée à V05 ; à inscrire au manifeste
- M5-L05 : valide — +identité typée, pas de chaîne libre, lint des noms orphelins / −partage entre îles dépend de l'ordre de chargement ; `match-element` ne vaut que same-document / conflits: M2-L05, M3-L08, M4-L05 (doublon, à garder), M1-L07 / cohérence: ok (S01 référence seule ; `defineShared` calqué sur `defineMotion`)
- M5-L06 : valide — +aucun verbe pour une page, un seul point d'entrée par routeur / −signature `motion.navigate(update)` à unifier avec M4-L07 ; cross-document absent d'iOS 18 et Firefox ESR (R1) / conflits: M4-L07 (doublon), M2-L07, M3-L09, M1-L08 / cohérence: ok (V02, V07, V08) ; `view-transition-*` émis par le plugin, jamais par l'auteur
- M5-L07 : valide — +un seul nœud porte la présence, l'ordre de sortie suit le DOM / −sortie inverse hors des options fermées ; gros sous-arbre retenu / conflits: M2-L08, M3-L10, M4-L09, M1-L10 / cohérence: ok (V01, V02, V03) ; règle « racine seule » à inscrire au manifeste
- M5-L08 : conteste — +`data-presence` posé par le runtime, lisible par variantes Tailwind / −le rendu réduit instantané contredit le `disappear` réduit en fondu (§8.1 corrigé) ; la valeur `leaving` diverge de `exiting` / conflits: M4-L10, M2-L09 (doublon), M3-L10, M1-L10 / cohérence: exception : rendu réduit instantané contraire au défaut de `disappear` ; à corriger
- M5-L09 : valide — +une mauvaise combinaison verbe × option est détectée au typage, une seule table pour cinq formes / −messages TS plus longs ; construction à l'exécution hors typage / conflits: M5-L03 (options `interrupt` et `shared` à reporter dans la table) / cohérence: ok (S10, V09)
- M5-L10 : valide — +l'agent reçoit le cas et la forme exacte au moment de l'erreur / −fiches à charger, recettes à maintenir avec les frameworks / conflits: — / cohérence: ok (V09, V10, S10) ; fiche « cas » non verbale, justifiée
