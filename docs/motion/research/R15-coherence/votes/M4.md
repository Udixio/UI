# Vote M4 (intégration frameworks : React 19, Angular, Svelte 5, îles Astro, SSR, routeurs)

I01 : C (confiance 2) — un seul nom d'option (`direction`, valeurs start/end/up/down) pour le mouvement, `from`/`to` réservés aux valeurs de `defineValue` : évite la collision de I23 ; start/end tiennent en RTL, up/down restent physiques.
I02 : C (confiance 2) — la présence en `carry` est la seule continuité correcte : un `disappear` interrompu par un `appear` s'inverse (équivalent de `reverse()` WAAPI) au lieu de sauter ; le reste en `restart` ; `scrub` suit la position du défilement, sans reprise à gérer.
I03 : A (confiance 2) — `data-motion` ne porte qu'une sorte de valeur (un nom) ; les verbes nus deviennent des définitions livrées (`layout`, `scrub`, `loop`, §8.0 bis #5), ce qui supprime l'ambiguïté nom/verbe que B laisserait au lint.
I04 : B (confiance 2) — `data-presence` est écrit par le runtime seul, donc hors de l'espace `data-motion-*` auteur ; `leaving` est symétrique d'`entering` et proche de `animate.leave` d'Angular.
I05 : A (confiance 2) — le fondu est de l'opacité, pas un mouvement spatial (WCAG 2.3.3 n'exige pas l'instantané) ; règle uniforme : rendu réduit = fondu court pour apparition, sortie et révélation ; l'exception à `--udx-motion-scale` se documente une seule fois.
I06 : C (confiance 2) — une transition d'état (chevron, couleur) est une valeur continue : un `defineValue` à ressort reprend exactement (position et vitesse) par construction ; `emphasize` reste accentuation en `restart` ; A ferait dépendre le défaut d'une option, ce qui casse le défaut par verbe de I02.
I07 : A (confiance 2) — un seul espace `--udx-motion-*` ; aucun alias `@theme` `--duration-*` ou `--ease-*` qui écraserait l'échelle native de Tailwind ; les utilitaires passent par des noms `udx-*` distincts, à tester.
I08 : A (confiance 2) — `restart` ne coûte rien sur une boucle (pause et reprise conservent la phase via `animation-play-state` ou WAAPI) ; la pause obligatoire (WCAG 2.2.2, mouvement continu de plus de 5 s) est vérifiée par le lint ; la réduction fige sur la frame neutre, sans mouvement sans fin.
I09 : A (confiance 2) — l'identité d'un élément partagé se déclare (`defineShared`, `data-motion-shared`, option de `layout`) : ce n'est pas un mouvement ; `state` est résolu par I06, `page` par I18 (preset `route`), `follow` reste retiré.
I10 : A (confiance 2) — cache de la dernière géométrie stable, invalidé sur la racine suivie (ResizeObserver, MutationObserver, défilement des ancêtres) : React n'offre pas de lecture pré-mutation propre hors wrapper de classe, Angular est non tranché ; un seul point de lecture couvre les quatre environnements et les mises à jour asynchrones que C exclut.
I11 : D (confiance 2) — D : liste fermée et versionnée des attributs (A) ; la prop `motion` des composants n'est qu'une traduction en attributs, avec les mêmes clés que `data-motion-<option>`, sans clé propre (C) ; les doublons (`scope`, `keep`, `group`, `part`/`step`) se règlent dans leurs items (I15, I17, I19).
I12 : B (confiance 2) — `grid-template-rows` de 0fr à 1fr s'anime sans JS ni mesure : pas de mesure de hauteur (I10) ni de pré-mutation par framework ; SSR correct ; l'exception « preset sans verbe » est la même que `route` (I13) et se documente ; `inert` sur le contenu replié reste à la charge de l'adaptateur.
I13 : A (confiance 2) — `pulse` et `spin` sont les noms de `animate-pulse` et `animate-spin` de Tailwind, présents dans le même balisage ; renommer (`breathe`, `rotate`) supprime la confusion à la lecture sans alourdir chaque attribut d'un préfixe (C).
I14 : A (confiance 2) — trois crans suffisent pour une cascade (tight, normal, loose), déjà employés par R13 et R14 ; `fast`/`normal`/`slow` se confond avec les vitesses de ressort et mêle vitesse et espacement.
I15 : A (confiance 2) — `data-motion-part` évite `step`, déjà pris par la méthode `step` du handle de geste (M5-R08) ; `at` n'accepte pas de temps nu (token, étiquette, `+=token`) ; `'<'` est illisible dans un attribut HTML.
I16 : A (confiance 2) — seul l'ordre vu est celui que suit l'utilisateur (`order`, `row-reverse`, grilles) ; une lecture par liste en phase de lecture reste bornée ; `sibling-index()` est absent de Chrome 109, Firefox ESR et iOS 18 (dans `defaults`) et ne donne que l'ordre DOM : B impose deux chemins.
I17 : B (confiance 2) — suit la décision validée §8.0 #5 (natif d'abord, backend tracé) ; `match-element` couvre le cross-document et le cross-route que le FLIP ne couvre pas entre îles ; FLIP en repli, `defineShared` pour l'identité ; doublon de clé : le dernier monté gagne (le sortant est retenu, non réinscrit) ; l'écart de rendu entre navigateurs passe par les tests de conformance (phase 2).
I18 : A (confiance 2) — `run` est exactement le point d'accroche des routeurs (`withViewTransitions` d'Angular, `onNavigate` de SvelteKit, `viewTransition` de React Router) : capture avant mutation garantie par construction, `direction` nécessaire pour l'avant et l'arrière ; le branchement reste à écrire par routeur, c'est inévitable.
I19 : C (confiance 2) — sortie en place par défaut, comme `animate.leave` d'Angular et les outros de Svelte, donc le comportement attendu ; `pop` reste une option déclarée pour les listes qui doivent se réajuster ; `inert` et `aria-hidden` dès le début de la sortie, car un élément sortant ne doit plus être focusable.
I20 : D (confiance 2) — D : `data-state` pour tout état auteur (A, convention de Radix et shadcn) ; le moteur n'écrit jamais `data-hover` ni `data-focus` (C), les survols restent en CSS natif via `hover:` et `focus:`.
I21 : C (confiance 2) — §8.0 #4 est validé : le handle reste à six méthodes ; `grab`, `drag`, `release`, `settle` sont des événements observés, pas des commandes ; un canal `motion.on` se mappe ensuite sur la forme de sortie de chaque framework (`onX` React, `(x)` Angular, callbacks Svelte).
I22 : B (confiance 2) — les types de retour diffèrent (signal Angular, store Svelte, snapshot React pour une valeur ; handle pour une séquence) : une fonction par type garde les types précis et le tree-shaking ; les références en chaîne restent acceptées, typées par l'union générée du manifeste.
I23 : A (confiance 2) — un sens par nom, domaines publiés au manifeste, noms anglais : c'est ce qui rend le lint et les types d'agents fiables ; `from` réservé aux valeurs (cf. I01), `origin` pour la cascade, `duration`/`delay`/`easing` en toutes lettres.
I24 : A (confiance 2) — `reorder` est un comportement de `defineGesture` composé de `layout`, pas un verbe : la liste reste fermée à sept ; vitesse `exact` au pointeur et `estimated` ailleurs, dit honnêtement ; l'alternative clavier obligatoire est une propriété de type de `defineGesture`, donc vérifiée à la compilation.
I25 : D (confiance 2) — D : ressorts en tokens `spring.<rôle>.<vitesse>` avec les noms M3 Expressive (spatial et effects × fast, default, slow), paramètres physiques conservés pour la reprise (A) ; durées sur l'échelle M3 officielle `short1` à `extra-long4`, non `short` à `extra-long` (M1-R06) ; valeurs à vérifier sur les tokens M3 avant S1, comme le demande §8.1 bis Q8.
I26 : D (confiance 2) — D : forme `source`, `axis`, `range` pour la définition (C) ; variables écrites sur les cibles abonnées, jamais sur la racine, qui invaliderait le style des descendants (A) ; `<data value>` pour un compteur (sémantique, rendu serveur), `data-motion-value` pour référencer une valeur.
I27 : D (confiance 2) — D : découpage préparé par le noyau et rendu par le framework (B), pour que le SSR et React gardent leurs enfants ; copie `sr-only` du texte complet, morceaux en `aria-hidden` (A) ; `aria-label` sur un conteneur générique n'est pas valide en ARIA 1.2 ; brouillage hors v1.
I28 : D (confiance 1) — D : chargement par verbe déclaré au manifeste ; les verbes du premier rendu (`appear` au chargement) sont chargés avec l'île ou en modulepreload, jamais en idle ; `reveal` et `scrub` à l'intersection ; gestes à l'intention ; idle pour le reste (A).
I29 : C (confiance 2) — `revert()` est le nom juste : il remet le DOM dans son état d'avant (styles inline effacés), ce dont les adaptateurs ont besoin pour le double montage de React StrictMode et la fin de vie Angular et Svelte ; `inspect()` reste un outil de diagnostic, distinct du registre.
I30 : B (confiance 2) — les faits se vérifient en phase 2, mais un arbitrage bloqué sur un spike retarde toute la roadmap ; décider sous hypothèse écrite au manifeste, avec repli (`sibling-index()` vers rang mesuré, `match-element` vers FLIP) et test de conformance qui bloque la famille si le fait tombe ; règle d'adaptateur : `d` n'est jamais une prop rendue par le framework.
