# Votes M3 — R15 (cohérence transversale)

Expert : M3 (runtime global, observateurs, scroll, performance, reduced motion).
Critère : l'option qui rend l'ensemble le plus cohérent et le plus juste techniquement, en tenant compte des décisions validées (§8.0, §8.0 bis : natif d'abord, handle unique, un runtime par page, attribut qui nomme, liste fermée, tokens dans `--udx-motion-*`).
Confiance : 3 = certain ; 2 = choix net mais discutable ; 1 = arbitrage de goût.

I01 : B (confiance 2) — un mot par sens du mouvement ; `start`/`end` logiques pour le RTL, `up`/`down` physiques (vertical sans miroir) ; libère `from`, réservé à `defineValue`.
I02 : B (confiance 2) — `scrub` en carry (la position est la donnée, rien à reprendre), `loop` en restart (cycle) ; présence : `disappear` en carry (continuité de valeur, WAAPI suffit, la vitesse n'est exigée que si consommée), `appear` en restart.
I03 : B (confiance 2) — un verbe nu = définition livrée portant le nom du verbe (§8.0 bis #5) : une seule nature de valeur dans `data-motion`, pas de conflit avec « l'attribut nomme » ; le lint refuse les noms réservés.
I04 : A (confiance 2) — `data-presence` écrit par le runtime seul, `entering | present | exiting` reprend le vocabulaire établi de React Transition.
I05 : A (confiance 3) — un fondu d'opacité n'est pas du mouvement au sens WCAG ; une sortie instantanée est brutale, la retenue dure le fondu ; le jeton `--udx-motion-scale` ne multiplie pas le fondu.
I06 : C (confiance 2) — `emphasize` reste un accent en restart ; un changement d'état continu (rotation, couleur) est une valeur (transition CSS native, qui reprend déjà sans saut, ou `defineValue`) ; pas de huitième verbe.
I07 : A (confiance 2) — un seul espace `--udx-motion-*` pour tokens et variables runtime ; pas d'alias `--duration-*` (écrase l'échelle native de Tailwind) ; les utilitaires sont dérivés (`duration-udx-*`) sans second espace de tokens.
I08 : A (confiance 2) — `restart` cohérent avec I02 ; réduit = figé sur une frame neutre avec un état textuel (un spinner figé seul perd son sens) ; `pause` obligatoire `control | essential` (WCAG 2.2.2).
I09 : A (confiance 2) — `layout` couvre géométrie et identité, l'identité portée par `data-motion-shared` (cf. I17) ; pas de huitième verbe ; `follow` et `page` sortent du vocabulaire.
I10 : A (confiance 2) — en HTML pur aucun point de capture avant mutation n'existe (MutationObserver est asynchrone) ; un cache de géométrie lue en phase de lecture, invalidé par ResizeObserver, MutationObserver et scroll des ancêtres, est la seule voie commune aux cinq formes ; la transaction (C) reste une API explicite pour le JS.
I11 : D (confiance 2) — D : liste fermée et versionnée (A) avec fusion des doublons de B (`part`/`step`, `layout-id`/`shared`, `scope`/`keep`/`group`) ; les clés de la prop `motion` sont exactement les noms des attributs `data-motion-<option>` (C), sans clé supplémentaire.
I12 : B (confiance 2) — `grid-template-rows` 0fr vers 1fr est une transition CSS native, reprise native, sans mesure ni JS, à vérifier dans les navigateurs de `defaults` ; exception déclarée comme `route` ; `inert` et la visibilité suivent l'état.
I13 : A (confiance 2) — renommer `spin` et `pulse` (collision de sens avec `animate-spin` / `animate-pulse`), `pulse` réservé à `loop` ; `blink` retiré ou borné à 3 flashs par seconde (WCAG 2.3.1) ; un préfixe `udx-` est inutile si les noms livrés sont réservés au build.
I14 : A (confiance 2) — trois crans déjà employés par R13 et R14 ; le total de cascade reste plafonné par `--udx-motion-stagger-max` ; `fast | normal | slow` entrerait en collision avec les tokens de ressort.
I15 : B (confiance 2) — un seul attribut enfant (`data-motion-step`) et des relations nommées `after` / `with` : une étape inconnue est une erreur de type ; `at` en tokens et `'<'` sont trop cryptiques pour un agent.
I16 : A (confiance 2) — seul le rang visuel respecte `order`, RTL et grilles ; il est mesuré une fois par cascade en phase de lecture (une lecture batchée, coût négligeable) ; `sibling-index()` reste une optimisation future, pas un contrat.
I17 : D (confiance 2) — D : identité par `defineShared` + `data-motion-shared` (C), unique par document, le premier inscrit gagne, un sortant retenu est exclu du registre ; rendu par FLIP unique (A), mesure JS et animation WAAPI quand c'est possible ; `view-transition-name` exclu car le handle unique (§8.0 #4) ne le contrôle pas.
I18 : B (confiance 2) — `startViewTransition(update)` capture l'état avant la mise à jour par construction ; la direction passe en option et alimente `types` (natif) ; pas de `run` à résoudre par routeur ; repli : appel direct de `update`.
I19 : A (confiance 3) — sortie en place à l'index d'origine : aucune géométrie modifiée pendant la retenue, pas de `position: fixed` qui casse grilles et pourcentages ; les frères se réajustent après `finished` ; `inert` et `aria-hidden` dès le départ.
I20 : D (confiance 2) — D : `data-state` pour tout état d'auteur (A, convention Radix / shadcn) ; le moteur n'écrit ni `data-hover` ni `data-focus` et n'écoute ni `pointerenter` ni `focusin` (C) ; `:hover` et `:focus-visible` restent des variants CSS natifs, `layout` sous `hover:` reste interdit au lint.
I21 : C (confiance 2) — les événements (`grab`, `drag`, `release`, `settle`) passent par des événements DOM, sans coût sans écouteur ; le handle reste à six méthodes (§8.0 #4) ; `inherited` et `step` deviennent des propriétés de lecture ou des actions de gestes.
I22 : B (confiance 2) — une fonction par type permet le chargement par verbe (I28), le tree-shaking et des erreurs de type lisibles ; compléter par des références en chaîne typées pour les presets (C) pour garder la parité avec `data-motion="<nom>"`.
I23 : A (confiance 3) — un sens par nom, domaines publiés au manifeste (un nom porteur de deux sens est une façon de plus d'écrire la même chose, anti-objectif §2) ; `from` réservé à `defineValue` ; `origin` pour le stagger ; noms anglais.
I24 : A (confiance 2) — vitesse exacte au pointeur, estimée sinon, sans dépendre d'anime pour les gestes ; alternative clavier obligatoire et typée (WCAG 2.1.1 et 2.5.7) ; `reorder` reste une primitive de geste sans verbe.
I25 : A (confiance 2) — ressort = token dont les paramètres physiques restent disponibles pour la reprise exacte, `linear()` dérivé au build ; durées = échelle officielle M3 (`short1` à `extra-long4`) sans alias ; à aligner sur l'ordre exact des tokens M3 (vitesse puis rôle, à vérifier).
I26 : A (confiance 3) — variables sur les cibles abonnées : écrire sur la racine invalide le style de tout le sous-arbre ; la forme `source` / `axis` / `range` et `<data>` pour le SSR (C) sont à conserver.
I27 : A (confiance 2) — le SSR garde le texte source, le découpage se fait après hydratation ; `sr-only` plus `aria-hidden` est plus fiable qu'un `aria-label` sur un élément générique ; domaine `letters` segmenté par graphème (`Intl.Segmenter`).
I28 : C (confiance 2) — charger quand une cible existe et approche de la vue (IntersectionObserver avec marge), ou à l'intention ; pas de chargement sans cible, pas de dépendance à `requestIdleCallback` (absent de Safari, à vérifier).
I29 : C (confiance 2) — séparer le registre (fin de vie) du diagnostic (`inspect()`) ; nommer la fin de vie `dispose()` plutôt que `revert()`, qui est le nom de `createScope` d'anime : l'API publique ne doit pas porter le nom d'un moteur remplaçable (C2).
I30 : A (confiance 3) — la phase 2 fournit déjà Playwright : vérifier par spike les faits qui conditionnent des contrats (morph, `sibling-index()`, `match-element`, `requestIdleCallback`, `linear()`) avant d'arbitrer les choix dépendants.
