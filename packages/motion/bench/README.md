# Indicative motion benchmark

Build the package first (`npx nx build @udixio/motion`), install the Playwright Chromium browser, then run `pnpm --filter @udixio/motion bench`. The local Vite server serves the built providers and resolves their dependencies; the report is written to the ignored `bench/report.json`.

The report compares WAAPI and animejs providers, CSS transitions, and Motion's `animate`, each with 100 and 1000 elements in a fresh Chromium page with 4× CPU throttling. `scriptMs` measures synchronous animation setup, `longAnimationFrames` gives the count and total duration in milliseconds reported by Chromium's Long Animation Frames API, and `framesDropped` estimates missed 60 Hz frames from animation-frame intervals. Results depend on hardware, browser and environment; they are observational and have no pass/fail thresholds.

The PR workflow uploads a validated report for affected motion changes as a seven-day artifact. Its separate job is informational and should not be a required branch protection check. Shared-runner timings vary; there are no performance thresholds. The current report does not cover GSAP, Chromium traces, or leak tests, and therefore does not complete I3.

The nightly workflow runs the current Playwright Chromium, Firefox, and WebKit engines without the Nx cache. WebKit is not Safari, and neither real Safari nor Firefox ESR or the minimum `defaults` browser versions have been established here (C13 remains open). Scheduled GitHub runs can be delayed or omitted: maintainers must configure external monitoring for missing nightly runs as well as failures; this workflow does not provide it. A prerequisite for merging is branch protection configured to require a PR to be up to date with its target branch; this repository change does not configure that setting; changing the target triggers an `edited` run, but a base branch update alone must not be assumed to trigger a fresh PR run. These workflows do not guard publication; the release SHA trust chain remains a separate task.
