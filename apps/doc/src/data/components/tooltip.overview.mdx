## Usage

`Tooltip` displays informative text when users hover, focus, or click a
target. React wraps a single trigger child directly; Angular has no
equivalent to cloning an arbitrary projected element, so its `target` input
(pointing at the trigger element) is always required.

```bash
import { Tooltip } from "@udixio/ui-react"
```

Use `trigger` ("hover", "focus", "click", or an array of these) to control
how the tooltip appears, and `position` to place it relative to its target.

<Code
  codes={{
    react: tooltipBasicReactSource,
    angular: tooltipBasicAngularSource,
  }}
>
  <TooltipBasicReact slot="react" client:load />
  <TooltipBasicAngular slot="angular" client:load />
</Code>

## Rich content

`variant="rich"` renders a card-like surface with a `title`, `text`, and
optional `buttons`. Project custom content instead -- via `content` in React,
or `<ng-content>` in Angular -- to replace that built-in layout entirely; it
only renders when `title`, `text`, and `buttons` are all unset.

<Code
  codes={{
    react: tooltipRichReactSource,
    angular: tooltipRichAngularSource,
  }}
>
  <TooltipRichReact slot="react" client:load />
  <TooltipRichAngular slot="angular" client:load />
</Code>

control visibility; `defaultOpen` initializes uncontrolled state.

## Delays

Use `openDelay` and `closeDelay` (ms) to tune the hover/focus behavior.
Defaults: `openDelay={400}`, `closeDelay={150}`. Focus and click transitions
are always immediate; only hover in/out is delayed.

## Motion

The open/close opacity and scale transition is implemented once with
Anime.js in `@udixio/core/dom` (`createTooltipTransitionController`), so
React and Angular share identical timing, reduced-motion behavior, and
cleanup. Neither adapter implements its own version of this effect, and
neither depends on `motion/react`. Override timing with `transition`
(`{ duration, ease }`).

## Position

`Tooltip` renders through `AnchorPositioner`, which uses native CSS Anchor
Positioning where supported and falls back to tracking the target's
`getBoundingClientRect()` otherwise. `position` accepts `top`, `bottom`,
`left`, `right`, `top-left`, `top-right`, `bottom-left`, or `bottom-right`;
it defaults to `bottom-right` for `variant="rich"` and `bottom` otherwise.

## Keyboard

| Keys | Actions |
| --- | --- |
| Tab | Focus lands on the target element, if focusable |
| Escape | Closes an open tooltip |

## Accessibility

- Provides `role="tooltip"` and links to its target via `aria-describedby`
  when open.
- The tooltip surface stays mounted at all times, hidden with `inert` and
  `aria-hidden` rather than unmounted, so it can animate out; expensive
  custom content is not torn down until `Tooltip` itself unmounts.
